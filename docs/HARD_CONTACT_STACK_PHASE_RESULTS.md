# H3 着地位相の頑健性

前回の同品質比較で選んだ設定を固定し、初期高さへの依存を検証する。
Nativeは2 ms・正則化0・反復上限20、MuJoCo 3.9.0は15.625 µs・
solref `(2e-6,10)`・Newton/Euler・反復上限200。
3段、上段3 kg、他の箱1 kg、摩擦ゼロ、評価時間2秒を固定する。

位相 p = 0 / 0.2 / 0.4 / 0.6 に対して、箱間と床の初期間隔を
`gap = 0.5 × 9.81 × ((16+p) × 0.002)²` とする。
これは解析的自由落下の最初の床接触時刻を、Nativeのステップ内でずらす設定。
MuJoCoの刻みでの位相も0 / 0.6 / 0.2 / 0.8となる。
四分の一ステップずつでは刻み比128によってMuJoCoの位相が同じになるため、
両方で位相が変わる値を使う。数値積分での実際の接触時刻を保証する式ではない。
また初期位置・衝突速度・箱同士の接触タイミングも変わるので、純粋な位相だけの
因果分離試験ではなく、狭い範囲の初期高さの頑健性試験である。

既存H3の全幾何・エネルギー・荷重伝達・静止のゲートを使い、失敗に合わせて
設定や閾値を変更しない。全4条件で両エンジンが合格した場合だけ費用比を出す。
各条件で監査を2回、計測前ウォームアップ1回、新規ワールドで計測5回を行い、
監査トレースの完全一致と計測時の最終状態一致を要求する。
一つの論理CPUに固定し、エンジンの実行順をケースごとに交互にする。
費用は生成・IPC・ECS同期・監査を除いたbackendバッチのみ。

```bash
python scripts/contact_benchmark/stack_phase.py target/release/examples/stack_drop /tmp/phase
python scripts/contact_benchmark/stack_phase.py target/release/examples/stack_drop /tmp/phase --verify
```

完全なfloat64状態を`.npy.gz`へ無損失保存する。検証器はファイルのハッシュ、
全8ケースの存在、固定した設定、全品質指標、費用中央値、比較適格性を再計算する。
CIはNativeの4位相の合格を統合テストで要求し、両エンジンの全トレースも保存する。
検証器が成功しても品質不合格があり得るため、比較適格性は別に記録する。
4点の観測は、全ての位相や任意の高さ、摩擦付き接触、任意姿勢を保証しない。

## 2026-10-30の結果

4位相すべてで両エンジンが全品質ゲートを通過した。
全8記録で完全再実行一致と計測最終状態一致を確認し、保存トレースから再検証した。

| 4条件の集計 | Native | MuJoCo |
|---|---:|---:|
| 物理1秒あたりの費用（ケース中央値の等重み平均） | 20.080 ms | 764.622 ms |
| 最大めり込み（床・箱間） | 8.86×10⁻¹¹ m | 6.578 µm |

費用比MuJoCo/Nativeは **38.078倍**。前回の別条件での37.858倍に近く、
この4つの高さでも大きい刻みを使える利点を維持した。
Nativeは1秒500ステップ、MuJoCoは64,000ステップであり、
この比は同じ刻みのカーネル速度比較ではない。統計的信頼区間でもない。
