# 深積層を法線一括解法で解き、接触残差を検証する

基準は `5794735a`（#489）。4・8・16段の摩擦あり積層では、従来の点ごとの反復が
100ステップ中14・73・71ステップで上限200回に達していた。
既存の法線active-set解法を、接線方向に静止する小規模な摩擦接触にも適用する。
反復上限・許容値・正則化は変更しない。

## 採用条件とフォールバック

従来の摩擦なし経路は2〜32接触のまま。摩擦ありでは2〜64接触で、
自由接線速度の各成分が既存の速度許容値以内の場合だけ候補を試す。
いずれも正則化0、relaxation 1、有限で正の速度許容値が必要。
候補生成は既存の階数を考慮した消去法とactive-setを使い、追加コンプライアンスは入れない。
予算は従来どおり `min(max_iterations, 2 * contact_count + 1)` 回に制限する。

法線力積は非負、荷重点の法線制約速度は許容値以内、無荷重点は閉じないことを、
元の行列で検証する。さらに摩擦ありの荷重点では、法線力積が生む接線速度も
**元のDelassus行列から再計算**し、各成分が既存の許容値以内であることを確認する。
ゼロの摩擦力積は円錐内にあり、この場合の荷重点はStickingとする。
法線荷重により横滑りが誘起される候補、特異・不整合な候補は採用せず、
元のwarm startを保ったまま既存Gauss-Seidel反復へ戻す。

単なる「自由接線速度がゼロなら採用」ではない。法線・接線の結合を含む検証が必要。
warm startからの変化量には、取り除く接線力積も含める。
剛体の冗長接触では力積の配分は一意でなく、荷重ゼロの角が生じる場合がある。
既存の法線速度テストは、各角が必ず正荷重という仮定を外し、総荷重0.11962 N sと
全角の法線速度・非負荷重を検証するよう修正した。

## 停止フラグとは別の残差監査

tower監査に、各接触の世界座標の法線・相対速度・接線力積・法線力積・摩擦係数・gapを
記録する `contact_samples` を追加した。各行の12要素はこの順序で、ベクトルは各3要素。
Python側は法線速度へ `gap / dt`（負gapは回復係数0.2倍）を足し、以下を再計算する。

- 全接触で法線力積の非負性、摩擦円錐、閉じる法線制約速度を検査。
- 荷重点では法線制約速度、円錐内部の摩擦点では接線速度を検査。
- 摩擦力積と滑り速度の最大散逸条件 `|λt| |vt| + λt・vt` を検査。

法線速度は1e-8 m/s、接線速度のノルムは2e-8 m/s、力積の実行可能性は1e-10 N s、
最大散逸の誤差は1e-10 Jを基準にする。荷重点と円錐内部の分類には1e-10 N sを使う。
接線速度は2成分の既存許容値をノルムで検査するため、この基準とした。
これは固定された剛体tower条件の監査であり、正則化付き接触に流用しない。
生データはバックエンドの接触診断から取得するため、エンジンから完全に独立した物理実装ではない。
ただしソルバーの停止フラグや候補採用結果から残差の合否を推定しない。

## 比較方法

`contact_static_normal.py` は旧版・新版をそれぞれ独立に監査し、各版内で全ステップの
決定的リプレイと計時・監査の最終ハッシュ一致を確認する。接触力積の解法が変わるため、
旧版と新版のビット一致を要求しない。旧版の失敗もレポートに保持する。
CPU固定・ウォームアップ後、各条件5回の前後交互測定。開始順を反転した2セットを保存する。
速度測定は監査を無効にし、stepとECS同期のみを計時する。

GS反復数0は「演算なし」ではなく、法線active-set解法で終了したことを表す。
active-set回数は `ContactSolution.normal_block_iterations` に記録されるが、
今回のNative接触点診断には含まれない。コスト評価には実測のstep時間を使う。

## 限界

軸に揃った静止方向の荷重が対象で、任意の滑りや回転のある積層を高速化する手法ではない。
64接触を超える摩擦島も従来反復を使う。0.2秒の落下・接触立ち上がり試験であり、
長時間の静止平衡やロボット操作の性能、MuJoCoに対する優位性は未評価。
