# Hard contact：非貫通品質と計算コストで勝つ

2026-10-30。LeKiwi＋SO-101開発の優先課題を、関節ストッパー比較から独自接触ソルバの品質・コスト比較へ移す。
実機なし。以下は評価・実装計画であり、MuJoCoに対する優位性の測定結果ではない。

H1を実装し、[48設定の結果と最速候補の追加条件での失敗](HARD_CONTACT_DROP_RESULTS.md)を記録した。

## 目標と判定

**接触侵入・滑り・安定性の合格条件を満たす設定の中で、シミュレーション1秒あたりの計算時間を最小化する。**
比較の主役は`rne_physics_native`対MuJoCo。Rapierは別系列の参考値とする。
これまでのSO-101比較はRNE/Rapierであり、独自接触ソルバの性能根拠には使わない。

hard contactは非貫通制約を解く方式であって、有限刻み・有限反復で常に幾何学的侵入ゼロを保証する名称ではない。
接触検出漏れ、積分による回転、未収束、既定の正則化まで含めて評価する。
「ゼロ」は表示桁の丸めで定義せず、物理寸法で明記した許容侵入量と検出限界を添える。

評価図の横軸を計算時間、縦軸を最大侵入量とする。摩擦・エネルギー・安定性の不合格点も隠さず表示する。
同じ品質で高速、同じ計算予算で高品質、の両方向で比較する。
各エンジンの合格設定のうち最速のものを比較し、既定値だけで勝敗を決めない。
未達条件や失敗試行を除外した平均値で優位を主張しない。

## 現在の実装から分かること

- `rne_dynamics/src/contact.rs`は摩擦円錐を扱う反復ソルバと、接触・関節制限を含む時間積分を実装している。
  ウォームスタートもある。ただし摩擦円錐を使うことと、有限反復で全体が厳密解に達することは別。
- 低水準`ContactSolverConfig`の既定正則化は0。一方、`rne_physics_native/src/lib.rs`の
  `NativeBackendConfig`は`NATIVE_REGULARIZATION = 1e-3`を設定する。
  冗長接触の荷重分配を安定させるが、法線方向の小さなコンプライアンスを導入する。
- 既定の接触候補マージンは0.02 m。これは許容侵入量ではない。
  高速運動で候補を取り逃がさないことや、候補化による早すぎる反発がないことは別途確認する。
- 既存の侵入回復処理は、侵入した状態から段階的に押し戻す。これを厳密な非貫通保証と混同しない。
- 接触行列`J M⁻¹ Jᵀ`と反復処理がある。どちらが支配的かは未計測なので、最適化対象はプロファイル後に決める。

既定値は直ちに変更しない。正則化ゼロと既定値の両方を測り、把持のねじれ・滑り・未収束を記録する。

## 共通試験

| 順序 | 試験 | 主に判定するもの |
| --- | --- | --- |
| H1 | 球の落下・静止支持、摩擦なし、反発ゼロ | 侵入、衝突時刻、法線力積、静止ドリフト、計算時間 |
| H2 | 箱の落下・積み重ね、質量比1／10／100 | 多点接触、荷重分配、残留速度、崩壊、反復数 |
| H3 | 斜面・水平押し、固着と滑りの境界 | 摩擦円錐、滑り距離、摩擦によるエネルギー増加の有無 |
| H4 | 2指把持からSO-101の把持・持ち上げへ | 把持侵入、荷重偏り、物体の滑り・回転、保持成功 |
| H5 | 同じ合格設定を独立環境1／4／8／16で実行 | 実時間、メモリ、リセット費用、環境間の独立性 |

まず解析形状でモデル誤差を抑える。同じ質量・慣性・形状・初期姿勢・重力・摩擦・反発条件を使う。
慣性座標変換と物理単位を確認し、初期侵入のある試行は回復専用の別試験とする。
MuJoCoの接触軟性・摩擦円錐・接触次元・margin/gap・積分法・反復・許容誤差を保存する。
RNE側の正則化、候補マージン、侵入回復、反復、サブステップも保存し、名前だけで同等設定と扱わない。

## H1の最初の実装単位

半径0.05 m、質量1 kgの球を水平面から表面間距離0.10 mに静止配置する。
球の慣性は`2mr²/5`、重力は9.81 m/s²、摩擦・反発は0、物理時間2秒。
解析的な初接触時刻は`sqrt(2h/g)`、初衝突直前速度は`sqrt(2gh)`。
衝突区間の力積は速度変化に加えて区間内の重力力積を考慮する。

初期の品質ゲート案は、最大侵入10 µm以下、最後の0.5秒の速度最大値1 mm/s以下、
初接触時刻差が刻み幅1つ以内、衝突区間の法線力積誤差1%以内。
無反発条件での跳ね上がりも最大表面間距離として記録する。
これはH1の提案値であり、全接触課題の普遍的な基準ではない。
実装時に検出時刻・衝突区間・静止判定と丸め誤差の扱いを仕様・解析テストで固定し、測定結果を見る前に版を付ける。

刻みは0.25／0.5／1／2 ms。反復上限や正則化・MuJoCoの接触設定も事前に列挙し、探索予算を両側で明記する。
同じ設定を使う検証条件として、質量0.1／10 kgと落下距離0.01／0.5 mを確保し、検証条件ごとの後付け調整はしない。
合格設定がなければ「未達」と記録する。許容侵入量を結果に合わせて広げない。

出力は、共通シーン、全設定、ソフトウェア版、ホスト・CPU割当、時系列、品質指標、反復・未収束、時間を含む。
Pythonプロセス間呼び出しを各ステップに挟んで性能比較しない。
まず各ランナー内でバッチ実行し、I/O・JSON整形は計測区間外に置く。

## 測定でごまかさないこと

- 侵入量は更新後の形状から別途再計算する。ソルバが保持する更新前の接触gapや補正後の描画座標を流用しない。
- 全ステップの最大侵入を記録する。定常値や平均値だけでは衝突時の深い侵入が隠れる。
  離散時刻で非貫通でも途中のすり抜けは否定できないため、高速条件では掃引検査または衝突時刻検出を確認する。
- 法線非負・摩擦円錐違反と、ソルバが使うgap・反発・正則化を含む制約残差を記録する。
  インパルス更新量が小さいことだけで、幾何学的非貫通や制約の合格としない。
- 重力・外力の仕事と衝突散逸を区別してエネルギー変化を測る。微小侵入でも不自然なエネルギー注入があれば不合格とする。
- 品質監査と性能測定は同じ設定で別走行する。性能測定の全軌跡収集費用を一方だけに乗せない。
- 同じCPU割当・スレッド予算、ウォームアップ後5回以上の中央値と分布を出す。
  接触検出・力学準備・接触行列構築・求解・積分を分け、物理ステップ全体とECS等を含む全経路の両方を測る。
  内部計時で費用が増える場合は、その計時付き実行を総時間の比較から分ける。
- 刻みが異なる場合はsteps/sだけでなく「物理時間1秒の計算費用」で比較する。制御周期は共通に保つ。

## 改善の順序

1. H1の両ランナー・解析テスト・更新後gap監査を作り、現状の品質対コスト曲線を取得する。
2. 非貫通に失敗するなら、接触候補の取り逃がし、離散積分、未収束、正則化のどこかを切り分ける。
   必要に応じて掃引検出・適応サブステップ・位置補正を検討し、その追加費用とエネルギー変化も計測する。
3. 合格後、支配的な費用に対して接触の持続IDとウォームスタート、独立接触群の分割、
   行列の再利用／行列を明示形成しない求解、摩擦求解の反復制御を順に比較する。効果は未検証。
4. H2〜H4で過剰適合と冗長接触の退行を検出する。品質を保てた設定だけH5へ進める。

最初の成果物は「最速hard contact」の宣言ではなく、非貫通品質を監査できる共通落下ベンチマーク。
そこで得た律速と失敗条件を根拠にソルバを改善し、対象課題と条件を明示して優位性を判定する。
