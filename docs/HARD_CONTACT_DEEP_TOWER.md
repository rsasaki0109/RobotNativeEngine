# 摩擦あり深積層の品質・コスト基準

2段bridgeの高速化だけでは深い積層の収束性を確認できないため、
`6c761d03`（#488）のソルバーを変更せず、4・8・16段の垂直積層を追加した。
結果は**全段数で品質判定に不合格**。幾何的なめり込みは基準内だが、
200反復で収束しないステップが残る。次の開発対象はこの収束性である。

## 固定条件

`contact_crowd COUNT audit|timing tower`。一辺0.1 m、質量3 kg、摩擦係数0.5、
反発0、慣性対角0.005 kg m²の箱を、中心高さ `0.055 + 0.105 * index` mに置く。
初期床・箱間ギャップは5 mm、重力9.81 m/s²、2 ms刻み100ステップ（0.2物理秒）。
正則化0、最大200反復、接触候補マージン20 mmは既存bridgeと同じ。
全箱のx/z座標は0、回転は単位クォータニオン。

監査では全ステップの姿勢、状態ハッシュ、動的支持辺、反復数、収束フラグを保存。
床は回転した8頂点、箱同士は全組合せの15軸OBBで独立にめり込みを測る。
判定基準は床・箱間の最大めり込み各1e-5 m以下、最終支持辺が隣接段の鎖と一致、
最終動的グラフが連結、全ステップのソルバー収束フラグが真であること。
フラグは既存の停止条件を表し、厳密な相補性残差の証明ではない。

品質不合格はデータから除外せず `passed: false` として保存する。
最初の未収束ステップと、めり込み基準を初めて超えたステップも記録する。
不正な時刻・姿勢・ID、変更された計測条件、監査と計時の状態不一致はエラーにする。
`--verify` は品質不合格の再現も検証するもので、終了コード0は品質合格を意味しない。

## 結果

CPU固定、ウォームアップ後の5試行中央値。時間はstepとECS同期のみで、
監査・初期化・JSON出力を含めない。変更前後の速度比較ではなく、新しい負荷の基準値。

| 段数 | 秒/物理秒 | 床めり込み m | 箱間めり込み m | 未収束ステップ / 100 | 最終支持辺 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 0.161 | 7.11e-7 | 2.12e-7 | 14 | 3 |
| 8 | 1.176 | 1.99e-6 | 6.63e-7 | 73 | 7 |
| 16 | 1.577 | 3.39e-6 | 2.72e-6 | 71 | 15 |

全段数で最初の未収束は28ステップ目（0.056秒）、最大反復数は200。
めり込み基準を超えたステップはない。最終支持辺は期待する隣接段の鎖と一致。
未収束の多さは深さに単純比例しないため、この3条件だけからスケーリング則を推定しない。
再実行で全ステップの状態・姿勢・接触診断が一致し、計時モードの最終ハッシュも一致した。

[ソース・バイナリ・生データのハッシュ](evidence/contact-tower-provenance.json)。
約1 MBの生データは `/workspace/artifacts/contact-tower-v1.json` に保存し、

## 再現

```bash
cargo build --release -p rne_physics_native --example contact_crowd
python scripts/contact_benchmark/contact_tower.py \
  target/release/examples/contact_crowd /tmp/tower.json
python scripts/contact_benchmark/contact_tower.py \
  target/release/examples/contact_crowd /tmp/tower.json --verify
```

NumPyを導入したPythonとLinuxのCPU affinity APIが必要。出力先は未使用のパスを指定する。

## 次の改善の判定

反復上限・停止許容値・正則化を据え置き、未収束ステップを減らせるかを評価する。
収束性の改善は軌跡が変わりうるため、旧版とのビット一致だけを合格条件にせず、
同一版の決定的リプレイ、独立OBB品質、支持関係と処理時間を併記する。
停止フラグを緩めて「改善」とせず、接触残差の独立監査も次の候補とする。

0.2秒の落下・接触立ち上がり試験であり、長時間の静止平衡、支持荷重の正確さ、
横方向の滑り、ロボット操作、MuJoCoに対する優位性は未評価。

## 検証

Rust releaseライブラリテスト121件、Python接触ベンチマーク99件成功。
新規8テストは深さ別の幾何・支持鎖、不報告の箱間/床めり込み、未収束、
不正な姿勢/時刻/ID、計時ハッシュ不一致、実バイナリの決定的リプレイを含む。
品質不合格をテスト失敗と混同せず、不合格結果が正しく保存・再現されることを確認する。

既存のseparated 1/16/64/128箱、stacks/clusters各64/128箱、bridge 15/31箱の
10ケースは、前回の保存バイナリと全監査結果が一致（計測時間のみ除外）。
release all-targets Clippy、fmt、依存境界検査成功。
