# 全箱が支持接触でつながる千鳥積み

## 評価する問題

従来のstacks/clustersは、多数の独立した2箱・4箱のグループだった。
本fixtureは上段の箱が下段の隣接2箱をまたぐ2段の千鳥積みで、
荷重を受ける動的接触だけで全箱が一つのグラフになることを検査する。
床をグラフに含めないため、床を共有しているだけの離れた箱は連結と判定しない。

15箱は下段8・上段7、31箱は下段16・上段15。
各箱は一辺0.1 m・3 kg・摩擦0.5、初期回転と速度0。
下段の中心高さ0.055 m、上段0.160 mで、床と上下間の初期隙間は5 mm。
横ピッチ0.105 m、上段は半ピッチずらし、全体を床の中央に置く。
2 ms刻みで100ステップ（0.2秒）、正則化0、反復上限200、接触候補距離20 mm。
63箱もexampleで実行可能だが、下記の理由から対比較の固定グリッドは15/31箱とした。

これは橋状の2段支持グラフであり、高層の山積みや3次元の乱雑な堆積ではない。
ロボット把持・横荷重・長時間安定性・MuJoCo比較も対象外。

## 品質と再現性

監査時のみ、各ステップで全箱の姿勢と既存の接触診断を記録する。
点別診断の法線インパルスが1e-10 N sを超える動的ペアを荷重支持辺とする。
最終ステップで全箱の連結と、上段各箱から所定の下段2箱への支持を確認する。
途中で辺が失われた場合は連結ステップ数に反映する。
全100ステップでソルバーの停止フラグを検査するが、独立したKKT証明ではない。

めり込みは接触生成器が返した候補だけに頼らず、監査姿勢から独立に計算する。
床は8頂点、動的ペアは全組合せのOBBについて15分離軸の最小重なりを評価する。
既存の `box.py` / `stack.py` の実装を再利用し、閾値は既存stackと同じ10 µm。
これはステップ終了時の離散的な交差検査であり、ステップ途中のCCD検査ではない。
100ステップの時刻・有限姿勢・単位四元数と、最初の自由落下ステップも検査する。

変更前後の状態ハッシュだけでなく、全姿勢・支持ペア・候補数・反復数などの
監査JSONが経過時間を除き完全一致することを要求する。
品質ゲートに失敗しても結果を削除せず `passed: false` として記録する。
不正なデータや前後不一致は検証エラーとする。

## 対照ビルドと速度計測

ベースブランチは `880b910c`（#483）。本PRにソルバーの変更はない。
両バイナリに本PRの同じexampleを使用し、対照版だけ
`crates/rne_dynamics/src/contact.rs` を `3edd40ca` の全行収束判定へ戻してビルドした。
その後ソースを戻して最終版を再ビルドし、保存した比較対象のSHA-256と一致を確認した。

CPUを1つに固定し、ウォームアップ後、前後交互に各5試行の中央値を比較する。
計時は100ステップとECS書き戻しを含み、初期化とJSON出力は除く。
速度計測では接触診断も姿勢記録も無効。最終ハッシュは監査実行と一致する。
各条件は1セットであり、単独マシンでの観測値を一般的な高速化率とはしない。

## 63箱の探索

最初に63箱も監査したところ1回で約108秒を要したため、反復測定は15/31箱に絞った。
63箱は最終支持辺62、全箱が連結したステップ78、最大反復131、未収束ステップ0。
独立形状検査の最大めり込みは床7.93e-10 m、箱同士3.62e-10 mだった。
[探索結果](evidence/contact-bridge-63-exploratory.json)に生データのSHA-256と保存場所を記録した。
これは単独監査であり、前後同等性・新規プロセスでの再実行・速度比較を確認した結果ではない。
監査時間を診断無効の実行コストとして流用しない。

## 制約と次の開発判断

接触グループを大きくした際のコストが次の課題。
探索監査の最大保持接触数は15箱で140点、31箱で300点、63箱で620点だった。
荷重支持辺（14/30/62本）とソルバーへ渡す接触点数を区別する。
接触点は荷重のない候補も含み、一辺に複数点あるため、辺の数だけでは
計算量を見積もれない。
今回の固定グリッドを回帰テストとして利用し、姿勢・支持・独立形状検査を保ったまま
密な接触行列の計算を減らす改善を評価する。箱数だけを増やした独立グループの
速度から、全体がつながる条件のコストを推定しない。

大きな姿勢・接触診断の生データは `/workspace/artifacts` に保存し、要約とハッシュを
コミットする。永続的に共有できるURLはまだない。
ワークスペース全体CIは容量制約により未検証（過去の全体ビルドは容量不足）。
