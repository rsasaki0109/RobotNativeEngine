# Separate fixed18 visitation diagnostic driver

This is a new prospective study, not an extension, retry or replacement of any
old six/18/72-world cohort. The driver was prepared from proven driver SOURCE
only. No historical raw or numerical report was read, no native binary/build
was executed, and no production checkout or GitHub object was changed.

The fixed order is `split_1_2`, `early_1_0`, `early_3_0`; within each profile,
negative then positive; within each sign, on then fresh then off. Each native
process creates one unchanged physical 143 fixture and performs one outer step.
The profiles select only public internal PGS/stabilization counts 1/2, 1/0 and
3/0 respectively. All use the same frozen executable. There are exactly 18
registered process/world slots. Labels are `PROFILE_SIGN_on|fresh|off`; fresh
passes `--observer on` in its own process.

`cohort_contract.py` supplies literal `CASES`, `PROFILES`, `load_spec`, and
`expected_driver_command`. `shared-contract-draft.json` records exact candidate,
wrapper, descriptor, index and lifecycle schema. Root fills
`candidate-template.json` from actual source/compiler/features/binary/reader
bindings and independent completed reviews. The template is not executable:
registration, binary, guards and admission are unset. Do not use a template hash
as if it were the final candidate/admitted wrapper hash.

The candidate preserves the proven field names and five registration artifact
roles. Root's `compiler_feature_receipt` descriptor binds its actual standalone
compiler/build/metadata/feature/binary and toolchain qualification receipts;
the independent pre-data admission must check that real relationship. Descriptors
have exactly `path`, `sha256`, `bytes`. Include actual source inputs, package/lock,
compiler/features and copied binary, protocol, driver source/test receipts,
reader source/test receipts and completed noncircular producer reviews in the
frozen closure. Candidate, admission and final wrapper authenticate one another
without including themselves circularly in `frozen_inputs`.

Separate reader and driver folders are supported. The unique frozen descriptor
whose basename is `cohort_driver.py` supplies the real driver command path;
`checked_driver_source` must be its sibling. Every actually loaded contract and
strict_io copy must be in the frozen inputs. The reader separately requires its
actually loaded schema/numeric/oracle/helper copies. Duplicate source paths and
ambiguous actual driver paths are rejected. Actual loaded driver/checked module
paths and authenticated wrapper/candidate/admission are checked at runtime.

Only run the new checked outer command after independent admission and source/
binary/tool/protocol freeze:

```sh
/usr/bin/python3 -B /absolute/new/checked_driver.py \
  --spec /absolute/new/admitted-wrapper.json \
  --spec-sha256 LITERAL_WRAPPER_SHA256 --launch-native
```

Without `--launch-native`, the default is validation only and creates no claims
or processes. Direct unchecked native collection is not qualified. Root must
retain the checked CLI's actual original exit0 separately; the reader requires
the original coordinator exit0, complete stdout terminal equal to disk, all18
original native exit0 and the durable source/binary/artifact bindings. Driver
completion alone does not prove scientific PASS or valid gzip/native state.

The driver exclusively creates the collection root, cohort claim, all18 folders
and process claims and `collection-index.json`. It fsyncs the root's parent and
all case/claim/index entries before any native spawn. The index maps every exact
argv and expected raw/claim/terminal path, including failed/unattempted slots.
Each case gets durable source-guard-before/after receipts and original stdout,
stderr, launch intent, start, terminal and whole raw output. One successful
collection has 18 whole raw files, nine files per case, and four collection-level
files; no output is replaced, selected out, resumed or rerun.

Launch/storage accounting is held in memory independently of successful terminal
writes. A Popen outcome can remain unknown; the known-started count is incomplete
when its completeness flag is false. A returned child's real start/exit survives
late ENOSPC and interruptions. The first failure stops subsequent slots and keeps
all reservations, partial files and original exits. Failed final terminal storage
forces a failed memory status/nonzero checked outcome instead of allowing a false
complete disk claim.

The checked Python coordinator owns a new session/process group. Native
collectors inherit that group. Outer failure cleanup signals the entire owned
group with SIGTERM, waits up to 10 seconds and uses SIGKILL/wait fallback when
needed. The driver CLI handles SIGTERM through its existing interrupted-child
retain/reap path. Cleanup actions/errors remain in the original checked receipt;
a failure cannot qualify. External uncatchable termination can leave incomplete
evidence; absent original exit/terminal proof remains unknown and cannot permit
replacement or a PASS.

Twenty retained fake-process methods passed at original exit0. They exercise
all18 ordering/argv/index/guards/directory barriers/no-resume, nonzero stop-first,
unknown Popen, late process/start/final/outer storage failures, owned-child
interrupt/timeout, source mutation, typed/hash/case tampering, split contract
folders and owned-group TERM/KILL cleanup. All real Popen calls and process-group
signals were mocked. Test inputs/partial outputs/failure artifacts remain under
`synthetic-tests/20261012T203939713063Z/`. They are not native data or scientific
qualification. Driver source before/after hashes matched.

Root preserves PR #410 and its old results while preparing this external study.
Standalone packaging uses an external package with its own empty workspace,
explicit dependency versions/features and its own lock/target, pointing at
unchanged vendored sources. The existing 141 selected root Cargo/lock/source map
must remain unchanged. Actual compiler metadata/features/checksums are bound;
standalone equivalence is not inferred from names alone.

The new frozen reader runs once after original collection gates pass. It must
derive each profile's event grammar from source, retain all18 full streams, and
check ON/fresh/OFF captured-state neutrality within each of the six profile/sign
groups plus literal fresh-ON completed records and absent OFF observers. It must
not assume the old 257/832 event schedule across all profiles or demand equal
states between different public parameter profiles. The claims remain limited
to captured state/source arithmetic/visitation. No motor-accuracy, full private
cache, physical-contact cause, correction adoption or hardware claim follows.
