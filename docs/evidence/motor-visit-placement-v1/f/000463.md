# Portable whole-file byte verifier preparation

`verify_literals.py` checks the declared manifest and local payloads with Python's
standard library. It never reads original absolute paths or imports archived
programs. Original paths are historical labels; local-only executable bindings
remain metadata and are not presented as recovered bytes.

The checker rejects duplicate JSON keys, bool/float descriptor sizes, noncanonical
or unsafe paths, symlinks, casefold collisions and Windows reserved names. The
full repository-relative prefix `docs/evidence/motor-visit-placement-v1/` plus each
payload name must be at most166 characters. Stored files remain at most1MiB.

Whole gzip representations restore the complete declared original SHA and byte
count. Restoration uses bounded-size chunks without writing decompressed files;
extra members, trailing bytes, truncation, CRC errors and excess output fail. The
original may exceed1MiB; ADR034 limits the stored representation.

The result describes declared literal bytes only. It does not assert scientific
accuracy, hidden-state equality, binary availability, complete historical coverage
or public retention. Existing native and scientific-reader outcomes stay unchanged.

New pure tests use invented bytes and deliberately rebound tampered gzip hashes so
framing/size/CRC checks are exercised independently of stored digest checks. Test
artifacts, command exits and actual prepared-copy results stay outside evidence.
