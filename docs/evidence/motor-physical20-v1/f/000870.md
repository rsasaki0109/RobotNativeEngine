# New isolated ForceBased physical diagnostic

This directory is preparation outside the product checkout. PR #411 remains
open at `423a3fd7f44128aa440afe47f937039de504f275`. No production behavior or
previously completed scientific dataset is changed by this preparation.

The sole candidate repeats the previously rejected global algebraic change
`D = inv(w + g)` for ForceBased internal motors. It is evaluated only in an
explicitly admitted contact-free spherical, single-DoF plant. Neither a
one-DoF check nor an observer switch proves contact freedom. AccelerationBased
normalization, limits, gains, caps, solve order, and telemetry are unchanged.
The candidate is a source copy, not a product feature or proposed default.

The complete pre-data table is in `protocol-source-template.json`: mass 0.5/2
kg; radius 0.1 m; outer duration 0.5/2 ms; one solver slice; one PGS iteration;
two stabilization iterations; stiffness 300 Nm/rad; damping 12 Nm s/rad.
Sixteen cases combine targets -0.001/+0.001 rad and caps 2/0.01 Nm; four zero
controls use cap 2 Nm. Two binaries times 20 cases times ON/fresh ON/OFF give
exactly 120 fresh processes and one new scientific reader. The earlier
12-process pilot proposal is superseded before data; it is never collected.
No retry, replacement world, gain search, or old scientific reader is allowed.

The independent physical reference uses geometric inertia `(2/5)mR^2` and
clipped implicit backward Euler. Velocity at position integration and final
writeback velocity are distinct quantities. The pre-data diagnostic tolerances
retain the existing inertia allowance `max(1e-8, 2e-5*abs(I))` and impulse
allowance `max(1e-8 Nm s, 0.01*abs(p_ref))`. Velocity, position and torque
allowances derive from that same impulse allowance; no fitted threshold is
introduced. Zero controls, saturation, nonfinite/missing evidence and
inconclusive results remain explicit outcomes.

These are fixed allowances for independent nominal-SI comparisons, not a
guaranteed propagated envelope for inertia or f32 input/rounding uncertainty.
Passing impulse and inertia checks does not imply passing velocity or position
checks. The geometric-inertia momentum quantities, public inertia quality and
nominal-to-f32 residuals are retained separately; no threshold is widened.

Before any valid native process, source/schema/reader/driver/compiler/feature/
binary/environment bindings and the complete budget must be frozen and
independently admitted. All original process exits, exceptions and partial
bytes must be retained. Preparation tests use synthetic data only. Actual
builds use locked dependencies, direct collector-only formatting, strict
Clippy and rustdoc, pure library tests and separate release binaries.

This diagnostic cannot replace the historical four accuracy criteria, exact
physical example 133–138 output preservation, the two heavy grasp tests, or
the required local/GitHub CI. It makes no claim of production adoption,
coupled contact causality, hardware validation, or increased practical maturity.
