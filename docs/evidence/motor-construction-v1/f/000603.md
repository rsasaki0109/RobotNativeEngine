# Prospective isolated motor-construction study

This is preparation, not frozen preregistration or a completed experiment. The
current PR #409, generation5 evidence, example141/142 schemas, production solver,
gains and criteria stay unchanged. The companion observer is being implemented
in a separate source copy; no Git worktree is created. No new native study world
has been launched. The separate scalar calibration remains FAIL0/4 and the
inverse-(w+g) intervention remains REJECTED.

The bounded question is whether actual captured motor-build inputs explain the
stored ERP/RHS/CFM/bounds in declared source order, and which actual velocity
advances the coordinate before stabilization. This is a diagnostic fidelity
question, not an assertion of a new defect, converged motor, coupled-contact
cause, hardware accuracy or greater maturity.

## Fixed prospective matrix

Use the exact isolated physical fixture from example141: fixed coincident parent,
one dynamic uniform sphere of radius 0.1 m and mass 1 kg, X-axis revolute joint with identity
frames, ForceBased position target, gravity/contact/passive damping/armature zero,
initial generalized velocity zero and no sleeping/CCD. Gains are the existing G1
posture pair: stiffness 300 Nm/rad and damping 12 Nm s/rad. The ceiling is 2 Nm.
One 1 ms outer interval has 32 small steps, one PGS pass and two stabilization passes.
No candidate solver intervention or gain/criterion tuning is included.

primary calibration or random independent sample. Construction and numerical
outcomes cannot rewrite previous calibration/recovery results.

## Planned interpretation and required checks

The separately versioned companion records actual constructor locals, matching
native row identity/J/W/CFM/accumulator bounds/cap and explicit row availability.
At AfterRowConstruction, reconstruct rounded inputs and ERP/RHS/CFM/bounds using
source-ordered f32 arithmetic. Do not substitute final ECS position, a later mass
cache, descriptor writeback or a stabilized row for the construction snapshot.
Limits use Rust f32::clamp's strict comparisons, which retain equal signed zero;
they differ from the generic impulse clamp. Missing input availability is not zero.

BeforePositionIntegration must capture actual multibody V after the generic-V copy
and before coordinate advancement; AfterPositionIntegration captures actual q/V
after advancement. Per-root events name the integration multibody explicitly.
AfterJointStabilization, FinalSlice and AfterVelocityWriteback retain separate
endpoints. Bind cache/slice/row/root identity and the actual source integration
operation before comparing q differences. Do not equate final V with the V used
for q, or infer a stabilization effect without its actual record.

Within each sign, require exact declared captured native/entity-state equality
ON/fresh/OFF and exact ordered companion telemetry equality between ON/fresh.
Keep absent OFF telemetry explicit. Captured-state scope excludes private pipeline
caches/full-set metadata unless explicitly added and bound; it is not universal
bitwise equivalence of all internal state. Every expected slice/build/endpoint must
be accounted for. Event-count details are pending the implementation and must be
frozen prospectively rather than selected from observed data.

Source arithmetic is eligible only in the declared normal-or-zero float domain;
subnormal/nonfinite inputs, tiny nonzero exact intermediates and overflow remain
explicit exclusions/failures. Source/compiler RN order binding cannot establish
unmeasured runtime MXCSR/FTZ/DAZ. SI backward-Euler comparison is a separate real
reference with a stationary target; diagnostic consistency never replaces the
unchanged1e-8/1% scalar accuracy criterion or grants patch adoption.

## Pure prototype delivered

construction_oracle.py checks the proposed constructor fields and nested v1 row.
It has no native engine import, process launcher or historical-data reader. Its
numeric helper is a literal copy of the already frozen pure generation5 helper,
with source hash recorded in numeric-helper-source.json. The initial eight tests
passed in pure-tests-attempt-1 (exit0): hand-derived half-valued cases, both gain
models, actual limit clipping, signed-zero preservation, output tampering,
malformed/missing inputs, nonfinite/subnormal exclusion and zero-authority bounds.
Independent initial review then reproduced two classification gaps before data:
a NaN calculated inverse duration was classified as an input exclusion, and
finite-input overflow could return an unstructured exception. Both were corrected;
the expanded ten tests passed in pure-tests-attempt-2 and the final bound-order
check passed in pure-construction-tests-attempt-3. The separate one-DOF endpoint
helper integration_oracle.py passed six tests in pure-integration-tests-attempt-2,
including rejection of final/stabilized velocity substitution, mixed identities
and boolean handles/indices that could compare equal to integers in Python.
Each arithmetic operation count covers only the modeled expressions, not the
whole native constructor/mass-matrix trace. The initial review does not certify
the changed bytes or the new endpoint helper; a final review is still required.
Only synthetic opaque word fixtures were read. The prototype is not yet a whole
cohort/schema/replay verifier and is not qualified against native observations.

Keep complete data files whole. If a future artifact exceeds the inline1MiB limit,
retain it locally and use an explicitly authorized external archive; do not split
or truncate traces or assume prior approval covers a different archive.
