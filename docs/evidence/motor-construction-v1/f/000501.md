# Prospective fixed-six constructor cohort tools

These tools are preparation only. They have read only new synthetic opaque-word
fixtures and injected Python process mocks. No native process/world, Cargo build,
old numerical trace/report, or publication has been executed by their author.
The pure constructor/integration/numeric helpers are literal copies from the
separately reviewed final prototype; their source SHA mappings are retained.

`strict_io.py` rejects duplicate keys, JSON floats/constants, incorrect integer
types/widths, malformed UTF-8/framing, unfinished or multiple gzip members,
trailing bytes and non-source gzip headers. The source header is exactly
`1f8b08000000000000ff`: GzBuilder mtime0, OS255, default compression, no flags,
name or comment. Compressed/raw sizes are bounded to 16/32 MiB per whole file.

`cohort_reader.py` admits exactly four success records per process, source-typed
checkpoint/native object ordering, fixed conditions, all observer availability,
full row/word shapes and native child/block identity. It requires exactly 257
companion events: 32 slices times eight source phases plus final writeback.
Unchanged stage v1 has 26 events per slice, 832 total: default warmstart on,
one PGS, two stabilization passes, zero additional friction iterations, one
supported motor, zero contacts. These counts come from the current source;
they have not been chosen from collected data. Stage/companion row and generic-V
snapshots, cache generation and integration root are cross-checked. No-op contact
boundaries in this source-bound no-contact fixture preserve recorded V/rows.

All 32 constructor inputs per ON process are checked against the frozen sign,
gains, duration, ceiling, absence of limits, +zero initial impulse, unit J,
stored weighted selector reciprocal and the copied ERP/RHS/CFM/bounds helper.
Native q chronology and `q += actual copied MB-V * h` are checked separately.
MB-V after stabilization remains the integration copy until final writeback;
it is deliberately not equated with current generic-V at those boundaries.
OFF telemetry must be null. Within each sign all initial/final captured native
checkpoints match ON/fresh/OFF exactly; ON/fresh completed-record bytes and typed
telemetry must match literally. Labels reside in run_start, not that record.

This reader does **not** independently decode postcard private layouts: the
source-bound collector performs exact native decode/reencode and publishes the
bytes. It does not replay every internal PGS operation, qualify full hidden-state
or private-cache equivalence, measure runtime MXCSR/FTZ/DAZ, establish convergence
or SI accuracy, infer physical force origin/coupled-contact cause, or adopt a
candidate patch. It checks actual captured constructor RHS expression fidelity;
that claim is separate from causal attribution. Exclusions/mismatches remain
non-PASS, and native failures/partial files retain their original full bytes.

## Noncircular mandatory registration

Root must create three new exclusive JSON files in this order, after the final
source/tool/binary freeze and independent review, before the first native launch:

1. Candidate spec, following `candidate-template.json` with all placeholders
   replaced. Its `frozen_inputs` bind the six runtime Python modules, actual
   selected collector/vendor/manifests and any configuration needed by the
   declared scope. The binary is a frozen **copy**, with actual SHA and whole size.
   Artifact roles bind protocol, actual collector source map, actual compiler/
   features/build receipt, independent producer review and actual pure-tool review.
   State an honest selected-source scope; a source map is not a hermetic compiler
   dependency closure. Paths must be canonical persistent /workspace paths.
2. Independent admission receipt with status
   `PASS_PRE_DATA_SOURCE_PROTOCOL_AND_DRIVER`, `reviewed_candidate_sha256` equal
   to the complete candidate file SHA, `binary` equal to its descriptor, and
   `frozen_inputs_sha256` equal to SHA256 of sorted-key compact JSON of its full
   frozen_inputs list. The independent owner verifies all real source/feature/
   compiler/binary/schedule/protocol evidence; this tool cannot establish trust
   merely from a string claiming PASS.
3. Final wrapper: exact keys `kind`, `schema_version`, `candidate`, `admission`.
   Kind is `admitted_isolated_motor_construction_cohort`, schema_version is 1;
   candidate/admission each have exact `path`, `sha256`, `bytes` descriptors.
   The independently supplied wrapper SHA is mandatory on both CLIs.

No candidate includes its admission descriptor, so admission can bind its full
SHA without circularity. No source descriptor is silently regenerated or relaxed.
The four named runtime variables must match registration; credentials/proxy
variables are inherited normally and are not printed or included in receipts.

## Driver and reader

Validation alone launches nothing and creates no collection output:

```text
python -B cohort_driver.py --spec ABS_FINAL_WRAPPER --spec-sha256 EXPECTED_SHA
```

Only a separately authorized native launch adds `--launch-native`. The output root
is newly and exclusively created, the cohort claim and all six process claims are
fsynced before the first launch, and actual original stdout/stderr/exit/PID/whole
output SHA are retained. Each fixed argv points to a new gzip file, which the
collector itself exclusively claims. Six cases are negative on/fresh_on/off then
positive on/fresh_on/off. A nonzero exit, timeout, missing output or source guard
failure stops further launches; remaining prelaunch claims are retained. There
is no resume, retry, replacement or cleanup of partial scientific outputs.

```text
python -B cohort_reader.py --spec ABS_FINAL_WRAPPER --spec-sha256 EXPECTED_SHA --result-root ABS_REGISTERED_OUTPUT_ROOT --output ABS_NEW_AUDIT_FILE
```

An actual schema/binding/partial failure writes an explicit non-PASS audit;
arithmetic mismatches/exclusions retain analysis records. Scientific originals
are never overwritten. These commands have not been run on native data.

The 15 initial world-free methods passed after the header/policy correction.
Final receipt/logs and guarded source map are generated by the checked pure
runner before handoff; the actual final method count is authoritative.
