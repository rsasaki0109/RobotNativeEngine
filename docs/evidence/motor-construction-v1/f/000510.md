## Future invocation

The only variable physics input is the fixed target sign, `negative` (-.001 f32)
or `positive` (+.001 f32). Observer is exactly `on` or `off`; ON explicitly enables
all three completed APIs: existing v1 impulse, existing v1 stage, and the separate
schema1 constructor companion. Fresh ON is a separate process using `on` and a
new label/output. Four flags are mandatory and may occur only once. Labels have
1-64 ASCII letters/digits/underscores/hyphens; output is an absolute new file whose
parent directory already exists. No gains, counts, timestep, alternative target,
retry or resume flag is exposed.

```text
FROZEN_BINARY --target negative --observer on --label negative-on --output ABSOLUTE_NEW_FILE.jsonl.gz
```

Root's future fixed process order is negative ON, negative fresh ON, negative OFF,
positive ON, positive fresh ON, positive OFF. This collector launches exactly one
fixture per valid invocation and calls pipeline.step once. It implements no
multi-case driver or publication. Do not invoke these commands during preparation.

## Raw framing and scope

OpenOptions::create_new claims the output before Fixture construction. The empty
file and parent directory are fsynced, then a deterministic gzip header and durable
`run_start` record are written before invoking the native constructor. The gzip
has mtime0, OS255, no name/comment, one member and integer-word JSONL. Every record
is flushed and the underlying file synced; final gzip finish/flush/file and parent
sync are required before exit0. Existing files are never overwritten or removed.

Successful framing is four records:

1. `run_start`: schema1, label/sign/observer, native32 width, fixed conditions as
   raw words/counts and explicitly bounded source-state scope.
2. `initial_state`: complete individually encoded native checkpoint before step.
3. `completed_interval`: ordinal1, complete native checkpoint, actual ordered
   `construction_companion` and `stage_v1` serde objects plus a word-preserving
   projection of the existing promoted-f64 impulse telemetry. All are null OFF.
4. `run_end`: collected/failed, distinct construction/step/record progress,
   completed interval count and any retained error. A terminal saying collected
   alone does not prove subsequent finalization or process exit0.

A caught step panic attempts `partial_native_observation` with the actual remaining
native checkpoint or its explicit read/serde error and completed-getter availability.
Private pending observer buffers are inaccessible and not fabricated as zeros.
Constructor, capture or I/O failures remain failed; prior records stay in the
exclusive output. Terminal writing/finalization may themselves fail, leaving an
incomplete file. The main program preserves a nonzero exit and reports combined
collector/terminal/finalization errors. The external driver must preserve its
actual original exit, logs and whole partial output. No retry is implemented.

Checkpoint records are grouped Body, Collider, Multibody and sorted by native
index/generation. The isolated fixture has two bodies, one collider, one unique
multibody and no impulse joint. Each object's postcard raw bytes are independently
exact-consumption decoded and reencoded through the same source-bound native type;
this is a source-bound roundtrip, not an independent decoder of private layouts.
The source-bound joint projection from 141 separately exposes actual coordinates
and rotation as f32 words. Full set metadata, broad/narrow phase, private pipeline/
solver/contact caches and observer buffers remain excluded. No universal hidden-
state equality is claimed.

Body position words are translation xyz, native quaternion xyzw; linear/angular
velocities and forces/torques are xyz. Public mass/effective-angular-inertia query
outputs are raw words (inertia matrix iteration is column-major), distinct from
a claimed stored first-row LU. Native multibody generalized V/damping,
per-link coordinates, joint rotation and descriptor impulse words are retained.
Link indices are actual vector iteration ordinals, not assumed private internal_id.
Parameter f32-word order is dt, min CCD dt, contact damping ratio/frequency, joint
frequency/damping ratio, warmstart, length unit, normalized allowed linear error,
max corrective velocity, prediction distance. Count order is solver, additional
friction, PGS, stabilization, min island size, max CCD substeps. Native parameter
postcard bytes are also retained. Gravity input is literal +0 xyz.

Companion and stage telemetry keep their actual public serde structs/raw native
words; the companion's source_contract is InternalUnitMotorConstructionV1 and
its event discriminator is phase. The collector does not calculate constructor
residuals or guess availability. Impulse telemetry's actual public f64 values,
including aggregates, become exact u64.to_bits words; Optional values retain null,
signed zeros are not normalized, and scalar_bits64 refers to that public promoted/
aggregate API rather than pretending all aggregates are stored native f32 words.
