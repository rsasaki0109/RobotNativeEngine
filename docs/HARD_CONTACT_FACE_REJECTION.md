# 箱の接触判定で不要な辺軸テストを省く

候補距離を狭めると落下の取りこぼしが生じるため、今回は既定の20 mmを維持し、
接触判定そのものの不要な計算を省いた。

## 変更

箱同士の分離軸判定は、まず両箱の6つの面法線を調べ、続いて9つの辺の組み合わせを調べる。
従来は面の判定で既に距離が候補範囲を超えていても、辺の判定まで進んでいた。
面の最大分離距離が `margin_m` を超えた時点で空の接触リストを返すようにした。

面を選ぶ順序と1e-9 mの同値判定許容値は従来どおり。
各面を調べた瞬間に打ち切るのではなく、従来選ばれた面の値で判定する。
距離がmarginと等しい場合も引き続き採用する。辺だけで分離する箱は従来の判定へ進む。
候補距離、接触点の順序、ソルバー、積分法は変更していない。

これは接触候補数を減らす変更ではなく、候補に入らない組の判定コストを減らす変更。
物体ペア全体の走査は依然O(N²)であり、空間インデックスの導入ではない。

## 実験

同じ床の上に、一辺0.1 m・3 kgの箱を0.15 m間隔で配置し、初期隙間5 mmから落とす。
1・16・64・128箱、2 ms刻み100ステップ（0.2秒）、摩擦0.5、正則化0、反復上限200。
箱同士の隙間50 mmは候補距離20 mmより大きく、各箱は床と接触する。
外力は重力だけで、箱同士が接触し続ける密集シーンとは異なる。

同一exampleを変更前後のバックエンドでreleaseビルドし、CPUを1つに固定。
各条件・各バイナリをウォームアップ後、前後の実行順を交互に変えて5回計測する。
計測はstepと毎ステップのECS書き戻しを含む。初期化、JSON出力、監査用ハッシュ計算は含めない。
タイミング測定中の接触診断は無効。

| 箱数 | 変更前 ms/物理秒 | 変更後 ms/物理秒 | 時間短縮 |
| ---: | ---: | ---: | ---: |
| 1 | 6.716 | 6.809 | -1.4% |
| 16 | 100.272 | 101.226 | -1.0% |
| 64 | 595.432 | 488.645 | 17.9% |
| 128 | 1706.552 | 1301.385 | 23.7% |

最終計測は本作業のビルド・テストが終了してから単独で実行した。
1・16箱は微増であり改善を確認できない。64・128箱でそれぞれ約18%・24%短縮した。

監査では100ステップそれぞれの物理スナップショットのstable_hashが前後で一致し、
全タイミング試行の最終ハッシュも一致した。箱の姿勢を含めた底面のめり込みと回転も検証する。
前回の初期隙間・水平初速・候補距離・刻みを変えた36条件も、変更前後で診断データが完全一致した。

箱1個の計測は短くばらつきが大きいので、そこから高速化の一般的な結論を出さない。
共用クラウド環境の計測であり、信頼区間や他CPUでの再現性は未評価。
MuJoCoとの比較や、ロボット把持・接触密集時の高速化は今回の結果に含めない。

  /path/to/before /path/to/after /tmp/contact-crowd.json --verify
