# H3 同品質の積み上げ比較 v1

MuJoCoの粗い刻みでの校正に続き、H3の評価器と品質ゲートを固定したまま
125 / 62.5 / 31.25 / 15.625 µsを順に探索する。
MuJoCo 3.9.0、solref `(2e-6,10)`、Newton/Euler、反復上限200を固定。
3段・上段1 kgと10 kgがともに合格する最初の刻みを選ぶ。
refsafeは有効で、時定数は刻みの2倍以上に制限される。

選択後は設定を変更せず、2/3段それぞれ上段0.3/3 kgの4条件を検証する。
この4条件は設定選択に使わない。Nativeは正則化0・反復上限20・2 ms固定。
形状、5 mmの初期間隔、慣性、摩擦ゼロ、重力、2秒間の評価は従来H3と同じ。

検証4条件で両方が全品質ゲートを満たした場合だけ、費用比を計算する。
一つの論理CPUに固定し、検証ケースごとに前後の実行順を交互にする。
各条件で全トレースの完全再実行一致、ウォームアップ1回、新規ワールド5回計測、
監査と計測の最終姿勢・速度の一致を要求する。
費用はECS同期・Python監査・モデル生成・IPCを除いたbackendバッチのみ。
速度の表現はNativeの姿勢差分とMuJoCoの状態速度という既存の差がある。

```bash
python scripts/contact_benchmark/stack_matched.py target/release/examples/stack_drop /tmp/stack-matched
python scripts/contact_benchmark/verify_stack_matched.py /tmp/stack-matched
```

各条件の全状態をfloat64の `.npy.gz` に無損失保存し、report.jsonには設定・MJCF・
ハッシュ・品質指標・全費用サンプルを記録する。途中経過をケースごとに保存する。
検証器は完全な校正順序と検証ケース集合、設定、トレースSHA-256、全品質指標、
最終状態、費用中央値、選択と比較の適格性を再計算する。

この試験は軸整列した最大3段、摩擦なし、固定された初期高さのみ。
連続非貫通、任意接触位相、大規模環境、摩擦付き接触、全MuJoCo設定での最適性を
保証するものではない。独立検証も質量と段数に限られる。

## 2026-10-30の結果

15.625 µsで校正2条件が初めて両方合格し、その設定で独立検証4条件も
両エンジンが全ゲートを通過した。計18件（Native校正2、MuJoCo校正8、
検証8）の全状態とハッシュ、選択条件、費用を再検証した。

| 検証4条件の集計 | Native | MuJoCo |
|---|---:|---:|
| 刻み | 2 ms | 15.625 µs |
| 物理1秒あたりの費用（ケース中央値の等重み平均） | 16.462 ms | 623.226 ms |
| 最大めり込み（床・箱間の最大） | 9.21×10⁻¹¹ m | 5.102 µm |

費用比MuJoCo/Nativeは **37.858倍**。
Nativeは1物理秒に500ステップ、MuJoCoは64,000ステップで、ステップ数は128倍違う。
1ステップあたりではNative約32.9 µs、MuJoCo約9.74 µsとなるため、
この結果は大きな刻みで品質を維持できる利点を示す。
同一刻みのカーネル性能比較や全用途での倍率ではない。
タイミングの5サンプルは観測値で、統計的信頼区間ではない。

[全集計とハッシュ](evidence/stack-matched/report.json)を保存した。
完全な生データと評価器スナップショットは別成果物 `stack-matched-v1.tar.gz` に収録。
ADR034に従って大きな生データをGitへ入れず、今回の実測の恒久公開URLは未取得。
CIは同じプロトコルで新しく計測し、集計と全トレースをartifactに保存する。
検証器成功と品質比較の成立は別であり、比較が不適格なら速度比を出さない。

Python 28件、全18記録の再検証、境界lintとdiff確認が通過。
Rust変更はなく、全workspaceチェックは先行のディスク不足のため再実行していない。
